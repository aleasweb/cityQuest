# План реализации: Flutter Клиент (CityQuest)

**Документ:** План разработки мобильного приложения iOS/Android для текущего MVP API.
**Подход:** Максимальная лаконичность, надежность (Best Practices 2025), Feature-driven architecture.

## 1. Технологический Стек
* **Фреймворк:** Flutter 3.x / Dart 3
* **State Management & DI:** `riverpod` (современный стандарт, строгая типизация, безопасность на этапе компиляции)
* **Сеть:** `dio` + `dio_cookie_manager` (нативная поддержка HttpOnly JWT cookies)
* **Сериализация:** `freezed` + `json_serializable` (иммутабельные DTO, pattern matching)
* **Роутинг:** `go_router` (стандарт от Google, deeplinks)

## 2. Архитектура (Feature-driven)
Изолированные бизнес-модули для поддержания чистоты кодовой базы:
* `core/` — фундаментальный слой (HTTP клиент с перехватчиками, Роутинг, Дизайн-система, локальное хранилище).
```
core/
  api/           # API-клиент (dio), перехватчики
  routing/       # go_router конфигурация (или в root/)
  storage/       # локальное хранилище (shared_preferences, hive)
  utils/         # общие утилиты
```  
* `features/auth/` — логин, регистрация, управление состоянием сессии.
* `features/quests/` — каталог, геопоиск (Haversine), фильтрация, детальная информация.
* `features/progress/` — engine прохождения (активный трекинг, проверка чекпоинтов, отправка координат).
* `features/profile/` — история прохождений, лайки.
```
features/name/
  data/          # DTO, репозитории, API-вызовы
  domain/        # бизнес-логика, модели
  presentation/  # UI, state management (Riverpod)
```
## 3. Интеграция с текущим API: Ключевые решения
1. **Аутентификация (HttpOnly Cookies):**
   * Использование `dio_cookie_manager` + `path_provider` обеспечит работу с HttpOnly cookies идентично браузеру.
   * *Фолбэк:* так как endpoint возвращает токен в теле (`token: response.token`), его можно безопасно перехватить и использовать как `Bearer` заголовок, если политики WebView/ОС заблокируют cookies.
2. **Геолокация (Ключевая фича):**
   * Запрос строгих пермиссий `ACCESS_FINE_LOCATION` (Android) / `NSLocationWhenInUseUsageDescription` (iOS).
   * Использование `LocationAccuracy.high` во время прохождения.
3. **Производительность:**
   * Имплементация client-side кеширования (например, для `/api/cities` с TTL 1 час) по аналогии с веб-клиентом.
   * Оптимистичный UI для лайков: мгновенное изменение состояния с фоновой отправкой запроса.

## 4. Roadmap реализации
1. **Sprint 1: Core & Auth.** Инициализация проекта, настройка слоев, реализация авторизации и управления состоянием пользователя.
2. **Sprint 2: Discovery.** Экраны списка квестов, карточки, фильтры. Интеграция `/quests/nearby` с базовой геолокацией.
3. **Sprint 3: Quest Engine.** Ядро геймплея: начало квеста, карта маршрута (`flutter_map`), активный GPS-трекинг, валидация чекпоинтов.
4. **Sprint 4: Polish.** Профиль пользователя, обработка краевых сценариев (потеря сети, отказ в гео-разрешениях), анимации и релизная сборка.
