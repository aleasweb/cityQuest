# Архитектура поддомена QuestStep

Поддомен `QuestStep` отвечает за управление отдельными этапами (чекпоинтами) внутри квеста.

## 1. Обзор архитектуры

Поддомен является частью домена `Quest` (`project/src/Quest/`).

**Слои:**
- **Domain:** Сущность `QuestStep`.
- **Infrastructure:** `DoctrineQuestStepRepository` для выборки этапов.

## 2. Сущность QuestStep

Сущность `QuestStep` (`quest_steps` таблица) имеет следующие архитектурные особенности:
- **Primary Key:** В отличие от большинства агрегатов, использующих UUID, `QuestStep` использует `INTEGER` с автоинкрементом (`IDENTITY`). Это связано с тем, что этапы жестко привязаны к квесту и редко существуют как независимые агрегаты во внешних системах.
- **Связь с Quest:** Связь осуществляется через поле `questId` (тип `UUID`). Это "мягкая" связь (soft relation) в стиле DDD, без жесткого `ManyToOne` маппинга на уровне Doctrine, что уменьшает связность агрегатов.
- **Уникальность:** Составной уникальный индекс `['quest_id', 'number']` гарантирует, что в рамках одного квеста не может быть двух этапов с одинаковым порядковым номером.
- **Геолокация:** Поля `lat`, `lng` и `radius` используются мобильным клиентом/фронтендом для определения того, достиг ли пользователь чекпоинта.
- **Статус:** Поле `status` (integer, по умолчанию 1) позволяет логически отключать этапы.

## 3. Индексы базы данных
Для обеспечения производительности созданы индексы:
- `idx_quest_steps_quest_id` на `quest_id` (для быстрой выборки этапов квеста).
- `idx_quest_steps_status` на `status` (для фильтрации только активных этапов).
