# Архитектура поддомена QuestLike

Поддомен `QuestLike` отвечает за систему оценок (лайков) квестов пользователями.

## 1. Обзор архитектуры

Поддомен является частью домена `Quest` (`project/src/Quest/`).

**Слои:**
- **Domain:** Сущность `QuestLike`.
- **Application:** Сервис для обработки переключения лайка (Toggle Like).
- **Infrastructure:** `DoctrineQuestLikeRepository`.
- **Presentation:** Контроллер для обработки POST-запросов на лайк.

## 2. Сущность QuestLike

Сущность `QuestLike` (`quest_likes` таблица) имеет следующие особенности:
- **Primary Key:** `UUID`.
- **Связи:** Хранит `userId` (UUID) и `questId` (UUID) как "мягкие" связи (без жестких Foreign Key связей на уровне ORM).
- **Уникальность:** Составной уникальный индекс `unique_user_quest_like` по колонкам `['user_id', 'quest_id']` гарантирует на уровне БД, что пользователь не может лайкнуть один и тот же квест дважды.

## 3. Денормализация счетчика лайков

Для обеспечения высокой производительности при сортировке квестов по популярности и при выдаче списков квестов:
- Общее количество лайков квеста хранится в денормализованном поле `likesCount` сущности `Quest`.
- При добавлении сущности `QuestLike` сервис транзакционно инкрементирует `Quest.likesCount`.
- При удалении сущности `QuestLike` сервис транзакционно декрементирует `Quest.likesCount`.

## 4. Вычисление isLikedByCurrentUser

При запросе списка квестов или детальной информации о квесте авторизованным пользователем:
- Сервис запросов делает дополнительную выборку из `quest_likes` по `userId` текущего пользователя и списку `questId` из результата.
- На основе этой выборки формируется boolean флаг `isLikedByCurrentUser` для каждого квеста в ответе API.
