# Архитектура домена Quest

Домен `Quest` отвечает за управление каталогом квестов, их поиск и выдачу информации.

## 1. Обзор архитектуры (DDD)

Домен располагается в `project/src/Quest/` и следует принципам DDD.

**Слои:**
- **Domain:** Сущность `Quest`, интерфейсы репозиториев (`QuestRepositoryInterface`), доменные исключения (например, `QuestNotFoundException`).
- **Application:** Сервисы для поиска и фильтрации квестов (`QuestQueryService`), DTO для ответов.
- **Infrastructure:** Реализация репозитория `DoctrineQuestRepository` (содержит сложную логику геопоиска и фильтрации).
- **Presentation:** REST-контроллеры (`QuestController`).

## 2. Сущность Quest

Сущность `Quest` (`quests` таблица) использует **UUID** в качестве первичного ключа.
Основные поля:
- `title`, `description`, `city`, `difficulty`
- `durationMinutes`, `distanceKm`
- `imageUrl`, `author`
- `likesCount` (денормализованный счетчик для быстрой сортировки и отображения)
- `isPopular` (флаг популярности)
- `latitude`, `longitude` (координаты старта квеста)
- `type` (тип квеста, по умолчанию `linear`)

## 3. Опциональная авторизация

Эндпоинты просмотра квестов (`GET /api/quests`, `GET /api/quests/{id}`) являются публичными, но поддерживают опциональную авторизацию.
- В `security.yaml` настроено `jwt: ~` и `roles: PUBLIC_ACCESS`.
- Контроллер проверяет наличие пользователя (`$this->getUser()`).
- Если пользователь авторизован, в ответ добавляется поле `isLikedByCurrentUser`, которое вычисляется через поддомен `QuestLike`.

## 4. Геопоиск

Для поиска квестов поблизости (`GET /api/quests/nearby`) используется расширение Doctrine для работы с гео-функциями (например, формула гаверсинуса или PostGIS) для вычисления расстояния между координатами пользователя и координатами квеста (`latitude`, `longitude`).
