## Context

Изменение затрагивает только UI-слой в веб- и мобильном клиентах. Серверная часть уже возвращает массив `pausedQuests` в ответе для `/api/user/profile?includeQuests=true`, что позволяет реализовать логику подсчета без бэкенд-изменений.

## Goals / Non-Goals

**Goals:**
- Заменить счетчик лайков на счетчик отложенных квестов в интерфейсах профиля Web и Mobile.
- Использовать уже имеющиеся в стейте данные `pausedQuests` для подсчета.

**Non-Goals:**
- Изменение структуры API.
- Добавление новой логики на серверной стороне.

## Decisions

**Решение 1: Подсчет на клиенте**
- **Как:** В React: выводить `profileData.pausedQuests.length` вместо перебора массива лайков `(profileData.completedQuests.filter(q => q.isLiked).length + ...)`.
- **Как:** В Flutter: Использовать `profile.pausedQuests.length.toString()` вместо хардкода `'0'` или вычисления лайков.
- **Почему:** Данные уже загружены, дополнительная логика не требуется.
- **Альтернативы:** Вычислять статистику на бэкенде и отдавать в мета-данных (избыточно для данной задачи).

**Решение 2: Обновление UI компонентов**
- **В Web (`UserProfile.tsx`)**: Заменить иконку `<Heart>` на иконку паузы (`<PauseCircle>` из lucide-react) или аналогичную, текст "Понравилось" на "На паузе".
- **В Mobile (`ProfileScreen.dart`)**: В `_StatCard` обновить текст с "В избранном" на "На паузе".

## Risks / Trade-offs

**Risks:** 
- У пользователей с большим количеством лайков пропадет визуальное подтверждение их активности.
- **Mitigation:** Для текущего этапа MVP метрика вовлеченности (отложенные квесты) важнее "коллекционирования". Лайки по-прежнему видны на деталях квестов.
