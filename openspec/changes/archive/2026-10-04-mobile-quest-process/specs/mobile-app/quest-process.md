## Purpose
Определяет поведение экрана прохождения квеста в мобильном приложении (Android/Flutter): пошаговое прохождение, проверка локации пользователя, пауза, список этапов и бесконечные попытки отгадывания.

## ADDED Requirements

### Requirement: Экран прохождения квеста
Мобильное приложение ДОЛЖНО предоставлять специальный UI-экран для активного прохождения квеста, отображающий текущий этап, задачу и элементы управления.

#### Scenario: Отображение базовой информации
- **WHEN** пользователь находится на экране прохождения квеста
- **THEN** приложение отображает: название квеста, номер текущего этапа и общее количество этапов, медиаконтент задачи (фото/текст/видео/аудио), кнопку "Проверить" ("Я на месте"), сворачиваемый список шагов и кнопку паузы.

### Requirement: Сворачиваемый список шагов
Приложение ДОЛЖНО отображать сворачиваемый список всех шагов квеста, скрывая детали будущих шагов для квестов линейного типа.

#### Scenario: Просмотр списка шагов (линейный квест)
- **WHEN** пользователь разворачивает список шагов в линейном квесте
- **THEN** пройденные шаги подсвечиваются ярким цветом и содержат полные данные, текущий шаг выделен, а все будущие шаги отображаются как неизвестные (скрыты детали).

### Requirement: Проверка геопозиции (бесконечные попытки)
Приложение ДОЛЖНО позволять пользователю неограниченное число раз проверять свою геопозицию ("Я на месте") для текущего шага.

#### Scenario: Успешная проверка локации
- **WHEN** пользователь нажимает кнопку "Я на месте" и его координаты находятся в радиусе чекпоинта
- **THEN** приложение отправляет запрос на сервер, получает подтверждение, показывает сообщение об успехе и переводит квест на следующий шаг (или завершает, если шаг последний).
- **TESTS**:
  - Backend: [UserProgressControllerTest::testCheckStepWorksCorrectly](../../../../backend/tests/UserProgress/Presentation/Controller/UserProgressControllerTest.php)

#### Scenario: Неудачная проверка локации (бесконечные попытки)
- **WHEN** пользователь нажимает кнопку "Я на месте", но его координаты вне радиуса чекпоинта
- **THEN** приложение отправляет запрос на сервер, получает отказ, показывает сообщение о неудаче (или оставшееся расстояние) и оставляет пользователя на текущем шаге, позволяя пробовать снова.
- **TESTS**:
  - Backend: [UserProgressControllerTest::testCheckStepWorksCorrectly](../../../../backend/tests/UserProgress/Presentation/Controller/UserProgressControllerTest.php)

### Requirement: Пауза квеста
Приложение ДОЛЖНО позволять поставить активный квест на паузу прямо с экрана прохождения.

#### Scenario: Постановка на паузу
- **WHEN** пользователь нажимает кнопку "Поставить на паузу"
- **THEN** приложение отправляет запрос на сервер, меняет статус квеста и перенаправляет пользователя на экран деталей квеста или главный экран.
