## Why

На экране профиля блок активного квеста дублирует карточку главной, но с другим заголовком и без пустого состояния, а карточки «на паузе» выглядят иначе и не дают возобновить или отказаться от квеста. Нужно выровнять профиль с уже существующим блоком «Активный квест» и дать понятные действия для отложенных квестов.

## What Changes

- Заголовок «Продолжить прохождение» на профиле заменяется на «Активный квест».
- При наличии активного квеста профиль показывает тот же `ActiveQuestBlock`, что и главный экран.
- При отсутствии активного квеста секция остаётся на месте и показывает текст «Нет активных квестов».
- Карточки квестов на паузе визуально повторяют блок активного квеста.
- У карточки на паузе есть кнопка «Отказаться» и кнопка «Продолжить» (последняя только если активного квеста нет).
- Локальные `_ActiveQuestCard` и `_PausedQuestCard` в профиле удаляются.

## Non-goals

- Изменения backend API и веб-профиля.
- Изменение поведения блока активного квеста на главном экране.
- Пустое состояние секции «Квесты на паузе» (секция по-прежнему скрывается, если список пуст).
- Миграции БД и правки `data/init-db/cityquest.sql` не требуются.

## Capabilities

### New Capabilities

- `design-system/paused-quest-block-mobile`: переиспользуемая карточка квеста на паузе с прогрессом и действиями «Продолжить» / «Отказаться».

### Modified Capabilities

- `mobile-app`: секции активного и приостановленного квеста на экране профиля (R06).
- `design-system/active-quest-block-mobile`: тот же `ActiveQuestBlock` переиспользуется на профиле; пустое состояние остаётся снаружи компонента.

## Impact

- **Mobile (Flutter):** `profile_screen.dart`, дизайн-система (`ActiveQuestBlock`, новый `PausedQuestBlock`), вызовы существующего progress API (`start` / `DELETE`) из профиля.
- **Frontend (Web):** нет.
- **Backend / API / БД:** нет, миграции не нужны.
